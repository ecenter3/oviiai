# OViiAI 機器人派工監控平台 系統規格書

Oct 11, 2026 · @Someone

本平台在一個控制室畫面上統一監控、派工與告警處理 3 個樓層、28 台、3 個品牌的巡邏機器人，並整合約 100 支固定攝影機與既有人臉辨識系統。第一期預計 2027/1/1 上線。

## 1. 專案概述

**目標**

1. 用機器人取代固定人力巡邏，全天候覆蓋辦公室、工廠與停車場。
2. 控制室一個畫面就能看到所有機器人、攝影機與告警，並能直接派工、遙控、對講。
3. AI 判斷不確定的事件交由人工複判，每一筆告警都有處理紀錄可追查。
4. 不綁定單一品牌：平台直接接各家機器人 SDK，日後可加入其他品牌。

**場域與配置**

| 樓層 | 區域 | 機器人 | 台數 | 充電樁 | 固定攝影機（暫定） |
| --- | --- | --- | --- | --- | --- |
| 1F | 辦公室 | 宇樹 B2（工業級四足） | 10 | 2 | 34 |
| 2F | 工廠 | 雲深處 X30（工業級四足） | 10 | 2 | 33 |
| B1 | 停車場 | 萬為 ANBOT-Y（輪式戶外安保機器人） | 8 | 2 | 33 |
| 合計 |  |  | 28 | 6 | 100 |

機器人不跨樓層。各樓層台數可在系統設定中調整。

**使用者**：控制室警衛、維修人員、主管、系統管理員（權限見第 3 節）。

**不在本期範圍**：大屏展示、機器人跨樓層搭電梯、補盲雷達、平台自行做人臉辨識運算、網路建置。

## 2. 系統架構

&#91;embedded content: 系統架構 · 5 層\]

各品牌差異全部關在轉接器裡，後端只透過訊息匯流排收發統一格式；影像不經後端，由影像閘道直接給瀏覽器。控制室只需瀏覽器，不必安裝軟體。

| 層 | 建議技術 |
| --- | --- |
| 前端 | React 網頁應用 |
| 後端 | TypeScript（NestJS） |
| 資料 | PostgreSQL ＋ TimescaleDB、Redis、MinIO |
| 訊息 | MQTT（EMQX 或 Mosquitto） |
| 影像 | MediaMTX |
| 部署 | Docker Compose，場內伺服器 |

以上均為開源軟體，無授權費。

## 4. 功能規格：監控導航

選單共 10 個分組、約 30 個頁面，畫面以已確認的可操作原型為準。以下每頁列出用途、顯示內容與可做的操作。

### 4.1 實時監控（首頁）

- **用途**：控制室主畫面，一眼看全場狀態。
- **顯示**：
  - 樓層切換（1F／2F／B1），平面圖上即時顯示機器人位置、朝向、狀態顏色與路線。
  - 攝影機點位，點擊開啟即時影像。
  - 充電樁位置與使用狀態。
  - 統計卡：線上／巡邏中／充電中／故障台數、今日任務數、未處理告警數。
  - 告警快訊列，最新在上；P1 告警彈窗並響鈴。
- **操作**：點機器人看詳情、進入遙控、急停、回充；點告警跳到處理頁。

### 4.2 機器人狀態

- **顯示**：每台機器人一張卡片——編號、品牌、樓層、狀態（待命／巡邏中／執行中／返回充電／充電中／遙控中／急停／故障／離線）、電量、目前任務、訊號、故障碼。
- **篩選**：依樓層、品牌、狀態。
- **操作**：急停／解除、回充、接管遙控、歸還自動。

### 4.3 實時遙控

- **顯示**：機器人前／後鏡頭即時影像、小地圖、電量與速度。
- **操作**：
  - 虛擬搖桿或鍵盤控制移動；放開即停，斷線 0.5 秒自動停止。
  - 雲台轉動與縮放、燈光開關。
  - 遠端對講：控制室與現場人員雙向通話。
  - 抓拍、錄影。
  - 自動跟隨：從白名單中選一人讓機器人跟隨（需機器人支援，待確認）。
  - 升降桿控制（保留給日後配有升降桿的機型）。
- **規則**：同一台同時只能一人遙控；接管時自動暫停其任務，歸還後繼續。

### 4.4 導航管理

- **路徑規劃**：在平面圖上點選航點組成路徑，顯示總長度。
- **巡邏任務**：路徑 ＋ 機器人 ＋ 時間 ＋ 重複方式（每日／週一至週五／週末／僅一次）。到點時若機器人急停或電量低於接單門檻，延後並發告警。
- **興趣點**：命名的重要位置（大廳、機房、出入口），可作為派工目的地。
- **充電樁定位**：每層 2 座的位置與對應機型。
- **特殊區域**：禁行區、減速區、靜音區。
- **待定項目**：傳送點、特殊點（停留動作）、任務分組、虛擬軌道、講解任務，是否需要待確認。

### 4.5 歷史與報表（第二期）

| 頁面 | 內容 |
| --- | --- |
| 能耗管理 | 每台每日充放電曲線、充電次數與時長、樓層彙總 |
| 任務報告 | 每筆任務的路線軌跡、耗時、經過點位、發現事件，可列印 |
| 歷史視頻 | 依機器人與日期播放錄影，時間軸上標示告警點 |
| 數據統計 | 任務數、巡邏里程、告警數與處理時效、可用率；可匯出 CSV |
| 運行日誌 | 每台每日狀態時間軸（待命、巡邏、充電、離線等） |

## 5. 功能規格：派工管理

&#91;embedded content: 派工流程 · 3 個判斷\]

派工頁提供任務範本（日常巡檢、環境監測、安全巡查、設備檢查、氣體檢測等）、手動建單、任務佇列與待審批清單。

**任務內容**：類型、優先級（P1 緊急／P2 高／P3 一般／P4 低）、樓層、目的地或路線、指定或自動選車、備註。

**任務狀態**：待審批 → 排隊中 → 執行中 → 已完成；或已暫停（被 P1 中斷）、已取消、失敗。

**充電規則**

| 規則 | 設定值（可調） |
| --- | --- |
| 自動回充 | 電量 ≤ 25% 時結束目前任務、前往充電 |
| 可接任務 | 電量 ≥ 40% |
| 恢復上線 | 充到 ≥ 90% 自動回到待命 |
| 充電排隊 | 每層 2 座樁，樁滿時依電量低者優先排隊 |

每層 10 台共用 2 座充電樁，推估同時在勤約 4–6 台；實際數字取決於續航與充電時間。

## 6. 功能規格：告警管理

&#91;embedded content: 告警處理狀態 · 7 個狀態\]

告警分兩類、三個等級，各等級的通知方式可在「告警設置」調整。

| 類別 | 告警項目 |
| --- | --- |
| 系統告警（設備本身） | 電量預警、低電量回充、訊號偏弱、機器人離線、急停、關節溫度過高、影像中斷、P1 插隊、指令失敗 |
| 業務告警（現場事件） | 人員入侵、黑名單人員、未註冊人員、火焰、煙霧、熱源異常、氣體濃度、溫度或濕度異常 |

| 等級 | 預設通知方式 | 範例 |
| --- | --- | --- |
| 一級（P1） | 全螢幕彈窗 ＋ 響鈴，需處理；第二期加簡訊 | 黑名單、入侵、煙霧 |
| 二級（P2） | 提示音 ＋ 告警列顯示，需處理 | 低電量、影像中斷、氣體 |
| 三級（P3） | 告警列顯示 | 訊號偏弱、未註冊人員 |

**告警頁功能**

- 依日期、等級、類型、樓層、機器人、狀態篩選，可匯出。
- 每筆告警顯示截圖或影片片段、發生地點（平面圖標示）、AI 信心度、處理歷程。
- 處理時可填備註、派機器人到場查看、一鍵回報上位。
- 告警設置：各告警項目的等級、是否彈窗、是否響鈴、是否需處理、簡訊接收人。

## 7. 功能規格：檢測與媒體

### 7.1 人臉檢測（第一期）

- 辨識運算由既有人臉系統負責，平台只接收結果並顯示。
- **顯示**：命中紀錄列表（時間、地點／鏡頭、拍到的臉、比對到的人、名單類別、信心度）；依日期、類別、樓層篩選。
- **名單類別**：白名單（員工）、黑名單、訪客、未註冊。
- **反應**：白名單語音問候；黑名單聲光警示並發 P1 告警；未註冊人員發 P3 告警。各類反應可在參數中調整。
- 信心度低於 70% 的結果不自動判定，進入「待人工複判」。

### 7.2 環境監測與定點檢測（第二期）

- 顯示機器人感測器回傳的溫度、濕度、氣體（如 CO）、煙霧、火焰等數值，及超標告警。實際可測項目依機器人配備而定。
- 定點檢測：在平面圖上設定檢測點與閾值，機器人巡邏經過時記錄數值；本期先預留介面。

### 7.3 媒體、抓拍與錄影

| 頁面 | 內容 | 階段 |
| --- | --- | --- |
| 抓拍圖片 | 依機器人、日期、事件類型瀏覽抓拍照片，可下載 | 第一期 |
| 錄像回放 | 手動或告警觸發的錄影片段，可播放、下載 | 第一期 |
| 音視頻管理 | 上傳機器人播放用的語音、警示音、警示圖片 | 第二期 |

**場域快速設定**（換場域或複製場域時使用）

| 功能 | 內容 | 階段 |
| --- | --- | --- |

## 9. 機器人接入規格

平台直接接各品牌機器人的 SDK，不經廠商雲平台。每個品牌一個轉接程式，把各家格式翻成統一格式；日後新增品牌只需多寫一個轉接程式。導航與避障使用機器人自帶功能。

| 品牌 | SDK 來源 | 費用 | 階段 | 待確認 |
| --- | --- | --- | --- | --- |
| 萬為 ANBOT-Y | 廠商提供 | 免費 | 第一期 | 文件內容、影像格式 |
| 宇樹 B2 | unitree\_sdk2（開源） | 免費 | 第一期 | 官方自主導航與自動回充介面 |
| 雲深處 | GitHub 開源 SDK | 免費 | 第二期 | X30 SDK 取得方式、自動回充 |

**平台從機器人收到的資料**（每秒 1–2 次）：位置與朝向、電量與充電狀態、運行狀態、目前任務、故障碼、能力清單、網路品質。

**平台可對機器人下達的指令**：導航到點、巡邏路線、遙控、停止／急停／解除、回充、雲台、燈光、對講、抓拍、錄影、跟隨。每個指令都要回覆執行結果，超時未回視為失敗並告警。

**座標校正**：每台機器人建圖後，在現場取 3 個以上對應點，把機器人地圖對齊到平台平面圖，誤差目標小於 0.5 公尺。

## 11. 非功能需求

以下為建議目標值，需依現場網路與硬體實測後定案。

| 類別 | 項目 | 目標 |

| 效能 | 即時影像延遲 | ≤ 1 秒 |

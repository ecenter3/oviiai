# 測試與部署

## 1. 測試計畫

| 層級 | 工具 | 範圍 | 何時執行 |
| --- | --- | --- | --- |
| 單元測試 | Vitest、pytest | 選車、充電排程、狀態轉換、權限、座標轉換、訊息格式 | 每次提交（CI） |
| API 測試 | Supertest ＋ 測試資料庫（Docker） | 每個端點的成功、權限不足、狀態衝突 | 每次提交（CI） |
| 模擬器整合 | 模擬器 ＋ 完整 Docker Compose | 派工→執行→完成、回充排隊、P1 插隊、離線告警 | 每日（CI 排程） |
| 端對端 | Playwright | 登入、監控、建單、審批、處理告警、權限隱藏 | 合併到 main |
| 壓力測試 | k6 ＋ 模擬器 | 50 台 × 2 Hz 遙測、20 個使用者、16 路影像同時播放 | M3 前 |
| 實機測試 | 現場測試人員 | 「開發規格書」Phase 0 清單、系統規格書驗收標準 | M2–M4 |

**必測情境**（每項至少一個自動化測試）

- [ ] 無可用機器人時任務排隊，有車空出後自動派出
- [ ] 電量低於接單門檻的機器人不會被選
- [ ] 兩個任務同時建立不會派到同一台
- [ ] P1 中斷任務後，原任務從中斷航點繼續
- [ ] 3 台同時低電量、只有 2 座樁：第 3 台排隊，第 1 台充到 90% 後讓位
- [ ] 審批開啟時非 P1 進待審批，P1 直接派出；超過 approvalUntil 後自動關閉審批
- [ ] 遙控接管時任務暫停，歸還後繼續；第二人無法同時遙控
- [ ] 遙控斷訊 500 ms 機器人停止
- [ ] 機器人離線 10 秒內出告警，恢復後自動重連
- [ ] 低信心度人臉事件進待人工複判；同一事件重複推送不重複建告警
- [ ] 非法的告警狀態轉換回 409
- [ ] 每個角色只看得到、做得到權限內的事；直接呼叫 API 也被擋
- [ ] 座標校正 rmse > 0.5 m 不能儲存

## 2. 伺服器準備

1. 安裝 Ubuntu Server 24.04 LTS，設定固定 IP、時區 Asia/Taipei、NTP 校時。
2. 安裝 Docker Engine 與 Docker Compose 外掛。
3. 準備資料磁碟挂載在 `/data`（資料庫、MinIO、備份）。
4. 防火牆只開 443（網頁）、8889 與 8189/udp（WebRTC）、1883（MQTT，限機器人網段）。
5. 以內部 CA 或自簽憑證啟用 HTTPS（瀏覽器用麥克風需要 HTTPS）。

## 3. Docker Compose

```yaml
# deploy/docker-compose.yml（節錄）
services:
  db:
    image: timescale/timescaledb:latest-pg16
    environment: { POSTGRES_PASSWORD: ${DB_PASSWORD}, POSTGRES_DB: rms }
    volumes: [ /data/pg:/var/lib/postgresql/data ]
    restart: unless-stopped
  redis:
    image: redis:7
    restart: unless-stopped
  emqx:
    image: emqx/emqx:5
    ports: [ "1883:1883" ]
    volumes: [ ./emqx:/opt/emqx/etc/custom ]
    restart: unless-stopped
  minio:
    image: minio/minio
    command: server /data --console-address :9001
    environment: { MINIO_ROOT_USER: ${MINIO_USER}, MINIO_ROOT_PASSWORD: ${MINIO_PASSWORD} }
    volumes: [ /data/minio:/data ]
    restart: unless-stopped
  mediamtx:
    image: bluenviron/mediamtx
    ports: [ "8889:8889", "8189:8189/udp" ]
    volumes: [ ./mediamtx/mediamtx.yml:/mediamtx.yml ]
    restart: unless-stopped
  api:
    image: ghcr.io/<org>/oviiai-rms-api:${VERSION}
    env_file: .env
    depends_on: [ db, redis, emqx, minio ]
    restart: unless-stopped
  web:
    image: ghcr.io/<org>/oviiai-rms-web:${VERSION}
    restart: unless-stopped
  nginx:
    image: nginx:stable
    ports: [ "443:443" ]
    volumes: [ ./nginx:/etc/nginx/conf.d, ./certs:/etc/nginx/certs ]
    restart: unless-stopped
  adapter-anbot:
    image: ghcr.io/<org>/oviiai-rms-adapter:${VERSION}
    command: python -m adapters.anbot
    env_file: .env
    network_mode: host          # 需直連機器人網段
    restart: unless-stopped
  adapter-unitree:
    image: ghcr.io/<org>/oviiai-rms-adapter:${VERSION}
    command: python -m adapters.unitree
    env_file: .env
    network_mode: host          # DDS 需要
    restart: unless-stopped
```

`.env.example` 必備鍵：`VERSION`、`DB_PASSWORD`、`JWT_SECRET`、`DATA_ENC_KEY`、`MINIO_USER`、`MINIO_PASSWORD`、`MQTT_API_USER`、`MQTT_API_PASSWORD`、`ADAPTER_KEY_ANBOT`、`ADAPTER_KEY_UNITREE`、`FACE_API_BASE`、`FACE_API_KEY`、`UPSTREAM_WEBHOOK_URL`、`UPSTREAM_WEBHOOK_SECRET`。

## 4. 發布與升級

1. 合併到 main 後，GitHub Actions 建置映像並打版本號（`v1.2.3`）。
2. 場內伺服器：改 `.env` 的 `VERSION` → `docker compose pull` → `docker compose run --rm api npm run migrate` → `docker compose up -d`。
3. 升級前自動備份資料庫；失敗時把 VERSION 改回上一版、還原備份。
4. 場內若不能連 GitHub，用 `docker save` 匯出映像檔帶入。

## 5. 備份與監控

| 項目 | 做法 |
| --- | --- |
| 資料庫備份 | 每日 02:00 `pg_dump -Fc` 到 `/data/backup`，保留 14 份；每月演練一次還原 |
| 設定備份 | `deploy/` 與 `.env` 加密後另存 |
| 健康檢查 | 各服務 Docker healthcheck；`/health` 異常時發系統告警 |
| 磁碟 | 使用率 > 80% 發二級告警 |
| 日誌 | Docker 日誌輪替（單檔 50 MB × 5） |
| 重啟 | 伺服器重開後全部服務自動啟動（`restart: unless-stopped`），轉接器自動重連機器人 |

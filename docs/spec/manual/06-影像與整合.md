# 影像與外部整合

## 1. 影像（MediaMTX）

約 100 支 IP 攝影機加機器人鏡頭，全部經 MediaMTX 轉成 WebRTC。只轉封裝、不轉碼，因此攝影機要設為 H.264（H.265 瀏覽器支援不一，需現場確認）。

- **路徑命名**：`cam/{cameraCode}`、`robot/{robotCode}/front`、`robot/{robotCode}/rear`。
- **按需拉流**：`sourceOnDemand: yes`，有人看才連攝影機，沒人看 10 秒後關閉。
- **設定產生**：後端在攝影機或機器人新增時，用 MediaMTX Control API（`/v3/config/paths/add`）新增路徑，RTSP 帳密不出現在設定檔。
- **播放權限**：MediaMTX `authMethod: http` 指向後端 `/internal/media-auth`；前端先向 `/streams/:key/token` 取得 60 秒短期憑證，播放時帶入。
- **播放**：前端 `VideoPlayer` 用 WHEP（`/{path}/whep`）；斷線每 3 秒重連。
- **監控首頁**：不同時開 100 路影像，只顯示點選的鏡頭；同時觀看上限 16 路（可設定）。
- **影像中斷告警**：後端每 30 秒輪詢 MediaMTX `/v3/paths/list`，正在被觀看但無來源的路徑超過 15 秒 → `stream_down` 告警。
- **錄影**：手動錄影與告警前後片段由後端以 ffmpeg 從 MediaMTX 拉 RTSP 寫檔，完成後上傳 MinIO（不全天候錄影；全天候錄影仍由既有 NVR 負責）。

```yaml
# deploy/mediamtx/mediamtx.yml（節錄）
webrtc: yes
webrtcAddress: :8889
webrtcICEServers2: []          # 場內網路不需 STUN/TURN
authMethod: http
authHTTPAddress: http://api:3000/internal/media-auth
api: yes
pathDefaults:
  sourceOnDemand: yes
  sourceOnDemandCloseAfter: 10s
  rtspTransport: tcp
```

## 2. 雙向對講

控制室與機器人現場人員即時通話。實作方式取決於各品牌 SDK 的音訊介面，先做方案 A，實機不支援再退到方案 B。

| 方案 | 做法 | 需要的 SDK 能力 |
| --- | --- | --- |
| A 即時 | 瀏覽器麥克風以 WHIP 推到 `talk/{robotCode}`；轉接器拉這路音訊送到機器人喇叭；機器人麥克風隨影像串流回來 | 機器人可接收即時音訊串流、影像含音訊 |
| B 按鍵說話 | 按住錄音、放開送出（`speak` 指令帶音檔）；現場聲音仍從影像串流聽 | 機器人可播放音檔 |

## 3. 人臉辨識系統（既有）

平台不做辨識，只收事件、查名單。拿到對方 API 文件後，在 `integrations/face` 寫一個對應層，輸出下列內部格式：

```ts
interface FaceEvent {
  externalId: string;        // 對方事件 ID，用於去重
  at: string;                // ISO 時間
  source: { cameraCode?: string; robotCode?: string };
  person?: { id: string; name: string; list: 'white' | 'black' | 'visitor' };
  list: 'white' | 'black' | 'visitor' | 'unknown';
  confidence: number;        // 0–100
  snapshotUrl?: string;      // 後端下載後轉存 MinIO
}
```

| 項目 | 做法 |
| --- | --- |
| 接收方式 | 對方支援推送 → 用 `POST /integrations/face/events`（API 金鑰＋IP 白名單）；否則每 2 秒輪詢並記住游標 |
| 來源對應 | 對方的鏡頭 ID 對應平台 camera 或 robot，對照表存 settings（`face.sourceMap`） |
| 產生告警 | black → `blacklist`（一級）；unknown → `unregistered`（三級）；white、visitor 只記錄不告警；信心度低於門檻 → 待人工複判 |
| 觸發機器人反應 | 依機器人參數「識別反應」送 `speak`／`light` 指令 |
| 名單查詢 | 代理對方 API，快取 5 分鐘；照片不落地儲存 |
| 待確認 | 機器人鏡頭是否交給人臉系統分析（對方拉 MediaMTX 的 RTSP 即可） |

## 4. 上位系統

格式依專案訂定，先做通用 Webhook：

- 告警按「回報上位」或符合自動回報規則時，POST JSON（告警、地點、截圖預簽名網址、處理歷程）到設定的網址。
- 標頭 `X-RMS-Signature: sha256=<HMAC>` 簽章；失敗重試 5 次（指數退避），仍失敗發系統告警。
- 上位回覆結果的介面在第二期依對方格式實作，收到後把告警從 reported 轉 closed。

## 5. 簡訊（第二期）

定義 `SmsProvider` 介面（`send(phone, text)`），待選定簡訊商後實作；同一告警同一人 10 分鐘內只發一次。

# 機器人接入

每個品牌一個 Python 轉接器程序，對內只講一套 MQTT 格式；後端完全不知道品牌差異。模擬器也是一個轉接器，後端無法分辨是否實機。

## 1. MQTT 主題

| 主題 | 方向 | QoS | retain | 內容 |
| --- | --- | --- | --- | --- |
| `rms/robot/{code}/telemetry` | 轉接器 → 後端 | 0 | 否 | 遙測，1–2 Hz |
| `rms/robot/{code}/event` | 轉接器 → 後端 | 1 | 否 | 事件（故障、到點、完成、充電開始結束） |
| `rms/robot/{code}/cmd` | 後端 → 轉接器 | 1 | 否 | 指令 |
| `rms/robot/{code}/ack` | 轉接器 → 後端 | 1 | 否 | 指令結果 |
| `rms/robot/{code}/teleop` | 後端 → 轉接器 | 0 | 否 | 遙控速度 |
| `rms/robot/{code}/online` | 轉接器 → 後端 | 1 | 是 | `true/false`；轉接器對每台設 Last Will |
| `rms/adapter/{name}/status` | 轉接器 → 後端 | 1 | 是 | 轉接器心跳與版本，每 5 秒 |

EMQX 設定：每個轉接器、後端各自帳密；ACL 限制轉接器只能寫自己品牌機器人的主題。

## 2. 訊息格式

定義在 `packages/shared/src/robot.ts`（zod），Python 端 `adapters/common/schema.py`（pydantic）要保持一致；CI 會用範例訊息檢查兩邊都能解析。

```ts
export type RobotState =
  | 'idle' | 'navigating' | 'patrolling' | 'teleop' | 'returning'
  | 'charging' | 'paused' | 'estop' | 'fault' | 'offline';

export interface Telemetry {
  ts: number;               // epoch ms
  pose: { x: number; y: number; yaw: number; floor: string }; // 已轉成平台座標
  battery: { pct: number; charging: boolean; voltage?: number };
  state: RobotState;
  speed?: number;           // m/s
  taskRef?: string | null;  // 平台 cmdId 或 taskId
  faults: { code: string; level: 1 | 2 | 3; msg: string }[];
  net?: { rssi?: number; latencyMs?: number };
  sensors?: Record<string, { value: number; unit: string }>; // 第二期環境
}

export interface RobotEvent {
  ts: number;
  type: 'fault' | 'fault_cleared' | 'waypoint_reached' | 'goal_reached'
      | 'goal_failed' | 'charge_started' | 'charge_finished' | 'estop_pressed'
      | 'sos' | 'obstacle_blocked';
  data?: Record<string, unknown>;
}

export interface Command {
  cmdId: string;
  ts: number;
  type: 'navigate' | 'patrol' | 'stop' | 'pause' | 'resume' | 'estop'
      | 'estop_release' | 'charge' | 'ptz' | 'light' | 'snapshot'
      | 'record_start' | 'record_stop' | 'speak' | 'follow' | 'follow_stop'
      | 'set_params' | 'lift';
  args: Record<string, unknown>;  // 座標一律是平台座標
  timeoutSec?: number;
}

export interface Ack {
  cmdId: string;
  ts: number;
  status: 'accepted' | 'rejected' | 'done' | 'failed';
  error?: { code: string; msg: string };
  result?: Record<string, unknown>; // e.g. snapshot 的 objectKey
}

export interface Teleop { lockId: string; vx: number; vy: number; wz: number; ts: number }
```

規則：

- 導航類指令先回 `accepted`，完成後再回 `done` 或 `failed`；即時類指令（ptz、light）直接回 `done`。
- 機器人不支援的指令回 `rejected` + `UNSUPPORTED`。
- 遙控：轉接器 500 ms 沒收到 teleop 就送零速度；速度上限依參數「導航速度」。
- 後端 10 秒沒收到某台 telemetry，或 `online=false`，即判離線並發告警。

## 3. 轉接器介面

每個品牌實作一個類別，共用的 MQTT、心跳、座標轉換、指令超時都在 `adapters/common`。

```python
class RobotDriver(ABC):
    """一台機器人的驅動。座標輸入輸出都是機器人自己的地圖座標，
    轉換到平台座標由 common 層負責。"""
    caps: set[str]

    async def connect(self) -> None: ...
    async def close(self) -> None: ...
    async def read_state(self) -> RawState: ...          # 位置、電量、狀態、故障
    async def navigate(self, x: float, y: float, yaw: float | None) -> None: ...
    async def patrol(self, points: list[Waypoint], loops: int) -> None: ...
    async def stop(self) -> None: ...
    async def pause(self) -> None: ...
    async def resume(self) -> None: ...
    async def estop(self, on: bool) -> None: ...
    async def go_charge(self, dock: dict) -> None: ...
    async def teleop(self, vx: float, vy: float, wz: float) -> None: ...
    async def ptz(self, pan: float, tilt: float, zoom: float) -> None: ...
    async def light(self, on: bool, mode: str | None) -> None: ...
    async def snapshot(self, camera: str) -> bytes: ...  # common 層上傳 MinIO
    async def speak(self, text: str | None, audio: bytes | None) -> None: ...
    def on_event(self, cb: Callable[[RobotEvent], None]) -> None: ...
    def stream_urls(self) -> dict[str, str]: ...         # {'front': 'rtsp://...'}
```

一個轉接器程序管理同品牌的多台機器人（設定來自後端 `GET /adapter-config/{name}`，以轉接器金鑰驗證）。單台斷線每 5 秒重連，不影響其他台。

## 5. 模擬器

- 依 `floors.robot_quota` 產生機器人（1F B2 ×10、2F X30 ×10、B1 ANBOT ×8），在平面圖範圍內走直線到目標。
- 移動 0.8 m/s；耗電每分鐘 0.5%，充電每分鐘 2%；可用 `--speedup 10` 加速時間。
- 支援全部指令；snapshot 回傳一張帶時間戳的圖。
- 可注入故障：`--fail-rate`、手動發送離線／急停／導航失敗，供測試告警。
- 與原型的模擬行為一致，可參考原型原始碼。

## 6. 座標校正

每台機器人建圖後，現場在 3 個以上分散位置記錄「機器人座標 (u,v)」與「平面圖上對應點 (x,y)」，以最小平方求仿射轉換：

```latex
\begin{bmatrix} x \\ y \end{bmatrix} = \begin{bmatrix} a & b \\ c & d \end{bmatrix} \begin{bmatrix} u \\ v \end{bmatrix} + \begin{bmatrix} t_x \\ t_y \end{bmatrix}
```

```python
import numpy as np
def fit_affine(src, dst):            # src: [(u,v)], dst: [(x,y)], n >= 3
    A = np.array([[u, v, 1] for u, v in src])
    px, *_ = np.linalg.lstsq(A, np.array([p[0] for p in dst]), rcond=None)
    py, *_ = np.linalg.lstsq(A, np.array([p[1] for p in dst]), rcond=None)
    pred = A @ np.vstack([px, py]).T
    rmse = float(np.sqrt(((pred - np.array(dst)) ** 2).sum(axis=1).mean()))
    return [px[0], px[1], px[2], py[0], py[1], py[2]], rmse
```

- 校正介面在「地圖管理」頁：在平面圖點位，輸入或從機器人目前位置帶入 (u,v)。
- rmse 超過 0.5 m 不允許儲存。反向轉換（平台→機器人）用矩陣反矩陣。yaw 加上轉換的旋轉角 atan2(c, a)。
- 同樓層同品牌共用一張地圖時，可一鍵套用到同組機器人。
